# Using OFS

How the window behaves. Download and command lines are in the [README](../README.md). Requirements are in [spec.md](spec.md).

## Profiles

JSON files in `~/.config/open-flexible-sync/profiles`, one file per name. `OFS_HOME` overrides `~/.config/open-flexible-sync` for profiles, the file database, and logs.

Import 5.71 copies the name, both paths, and the masks, and it fills direction, Standard or Exact Mirror, and the four timestamp checkboxes from the old profile. A mode digit of `1` is Exact Mirror and `0` is Standard. Right to left is the `YN` pair; the usual direction is left to right. Exclusions stay Ignore Totally. Versioning is not in those bytes, so `Older` stays off. A second import does not change a profile again, and it does not replace a path, a mask, a note, or a last result you already have. For profiles with no custom override, the group is the first word of the name, and only a prefix shared by multiple profiles becomes a collapsible heading. Single-profile groups stay as ordinary ungrouped rows, as in 5.71. Edit → Group / subgroups overrides this with a custom path such as `Work / Photos / Archive`; segments separated by `/` create nested expandable groups. A custom group can hold one profile. Search opens all required ancestor levels, Expand all/Collapse all include subgroups, and parent checkboxes select visible enabled descendants. Grouping does not rename physical folders, change sync paths, or remove the file database. A blank group field restores name-based grouping; batch renames preserve explicit custom groups. For a catalog with at least 12 profiles and three real groups, ordinary ungrouped profiles are placed in a collapsed `(ungrouped)` section at the top. It has the same tri-state visible-enabled selection and opens through search or Expand all. Small catalogs retain plain rows, and the virtual section never changes a profile's stored group. Expand all and Collapse all open or close every real group. Search matches the name and the group and opens groups that match. The status filter can show all, never run in OFS, clean, stopped, errors, or selected profiles. Not run in… takes a day count and shows never-run/undated jobs plus dated OFS runs at least that many days old. Available paths only additionally hides a profile unless both folders exist now. Filtering never changes the checked set; the counter still shows the number Run checked will scan. Each real group has a tri-state checkbox for selecting or clearing its visible enabled members. Disabled members are not selected; hidden filtered-out members are unchanged. A partly selected group shows an indeterminate checkbox. The overview has fixed Profile, Last run, Result, and Actions columns. A run scans only the checked profiles.

Edit can set direction, Copy only (no deletions), Exact Mirror, the exclusion mode, the timestamp rules, binary compare, `Older` for replaced files, and the file database. Copy only is stored as `standard`. Include filters keep `(all)` for everything; replacing it with rules such as `*.jpg` includes only matching files and leaves everything else out of copying and mirror deletion. Include and exclusion rules have separate rows with type labels; rules can be added, edited, removed, and tested against a relative path before saving. Min size, max size, min age, and max age leave a file out of the plan when it is outside those limits. Empty means that limit is off. A file outside the limits is listed as skipped: it is not copied and it is not deleted. The Skipped filter shows those rows. Don't Copy leaves the file visible, and Exact Mirror may delete the other side's copy. Ignore Totally hides the file from copy and from delete. In Exact Mirror, one file that exists only on the source and one file that exists only on the destination become a move when the timestamp rules call them the same file and the match is unique. Same-size duplicates stay a copy and a delete. That pairing does not use the file database. Standard copying still copies the new path and leaves the old one.

Symlinks has three explicit modes. Follow is the compatibility default: file and directory targets are scanned without following directory cycles; final copying must remain within the profile root. Preserve transfers the link itself, including its relative or absolute target text and dangling links, without reading or writing its target. Skip leaves links out of copy and mirror-delete planning. Dangling or unsupported followed targets and cyclic links remain undecided instead of being mistaken for an absent source. Preserved link/real-directory layout conflicts are refused by the apply preflight before any operation; resolve the tree layout or change the mode rather than relying on a partial run.

Compare file permissions and Compare file owner and group are off by default. They inspect file permission bits and numeric UID/GID separately from timestamp comparisons. In two-way mode, an equal-time metadata difference becomes an undecided row. Preserve owner and group when permitted uses the temporary file/link before atomic replacement and applies to Restore Older too. It fails safely rather than silently dropping ownership; this may require appropriate privileges. File mode and timestamps remain preserved on ordinary copies regardless. Folder ownership, ACLs, and extended attributes are not part of these switches. If owner comparison is enabled but owner preservation is not, a deliberate one-way comparison can continue to report a difference as expected.

Settings → Appearance offers System (the default), Light, and Dark. The choice is stored in the global Settings document as `theme`, applied immediately on Save, and restored at startup. System follows GNU/GNOME desktop color-scheme preferences when exposed through GSettings; otherwise it retains GTK's initial dark-theme preference. Light and Dark override that choice for OFS without changing desktop settings or any profile.

Settings holds the compare command and the global exclusions. Until you save that list, every profile ignores `.DS_Store`, `Thumbs.db`, `Temporary Internet Files`, `*.tmp`, `*.$$$`, and `*.~*`. Global masks are ignored totally. Saving an empty list turns them off.

`Older versions` is how many copies to keep. The newest is `Older/<path>`. The one before it is `Older/<path>.~1~`, and so on. The default is one, which replaces the previous archive. A higher number rotates them and deletes the oldest. Keep replaced files and Recoverable deletions are separate opt-in settings. The latter moves files deleted by synchronization into the same `Older` tree; unchanged empty folders are not archived. Import and existing profiles keep permanent deletion as the default.

Restore Older… in the header operates on the one checked profile. It is also available in Edit, including for a disabled profile. Select file versions and choose a destination outside both synchronized folders. Restoration copies the archive atomically without changing the archive or either live tree. Existing destination files are not overwritten. Relative paths are recreated below the chosen folder.

A missing folder fails that job with "volume is not mounted" and the next checked job still runs. Left volume and Right volume, when filled in, name the disk that must hold that folder. The scan does not start when that label is absent or when the folder is on a different disk.

Choose **Profiles → New window** for another main overview in the same OFS process. On Linux desktops that support launcher actions, right-click the OFS taskbar/dock icon and choose **New Window**. Each window retains its own checked profiles, search/filter state, scrolling, and dialogs. All windows share the profiles on disk and a per-profile operation lock: a second window cannot duplicate a scan, whole-folder copy, or comparison-plan copy that is already active elsewhere. A blocked action displays a status or preview message and starts no file operation. Different profiles remain independent, including parallel discovery scans. Running `./launch.sh --new-window` provides the same action from the checkout. Closing a main overview does not cancel an active scan. Its progress window stays attached to OFS, and the completed scan still opens its preview or multi-profile result after the original overview is gone. Cancel remains available in the progress window itself.

New profile is the first header action. The expanded Profiles menu contains New window, Import 5.71 profiles…, Import OFS profiles…, Export checked profiles…, Multi Edit checked profiles…, Replace paths in checked profiles…, and Rename checked profiles…. To replace paths after a mount-point change or moved folder, check the profiles first. The tool can replace case-sensitive text in both Left and Right paths (the default), Left only, or Right only. Optional prefix-only mode changes a leading path matching the complete folder or a complete folder boundary, not a similarly named sibling folder. Joining a replacement and an existing separator does not insert a doubled `/`. The scrollable live preview lists every affected side's complete old and new path. Review Changes… opens a confirmation. Nothing is saved during preview, and Cancel changes nothing.

Saving path changes updates only those Left/Right configuration fields; it does not move or rename folders on disk. Left/right volume labels, exclusions, other settings, and last-result text stay unchanged. The file databases of changed profiles are removed because they describe the old folders. The next run with the file database on records the new folders. If the actual volume label changed too, update the separate volume field deliberately before running.

Rename checked profiles… provides case-sensitive text replacement or prefix matching across checked profile names, with a complete old/new preview and confirmation. All names are validated against current profiles before any save: empty/padded names, names containing `=`, duplicates, and existing-name collisions are rejected without changing the profiles. Renaming preserves paths, masks, metadata options, and other settings, then removes the old-name file database and keeps the renamed profiles checked. Groups are recalculated from the new names. It does not move folders or historical log files on disk.

Multi Edit… changes one field across the checked profiles after showing affected names and values for confirmation. Field to change supports type-ahead search, so typing `cache` finds **Destination metadata cache**; its New value choices are explicitly **Off** and **On**. Available fields include direction, mode, exclusions, Disabled, Older retention, deletion safeguards, symlink handling, permission/ownership options, binary comparison, file database, all timestamp rules, and destination metadata caching. Cache has explicit Off and On choices; disable it to force normal destination discovery, or enable the persistent per-profile metadata cache. Left/Right volume labels, minimum/maximum file size, and minimum/maximum age are also editable. Sizes accept values such as `512`, `1.5 KB`, or `2M`, with empty or zero meaning no limit; ages accept fractional days. For include or exclusion masks, choose Add to keep each profile's existing rules or Replace to replace that entire list. All unselected fields, names, paths, notes, and last results stay unchanged. Disabled profiles can be changed or enabled even though their overview checkboxes are unavailable.

When a completed copy or new-folder operation refreshes profile results, the overview keeps its vertical scroll position and expanded groups. The viewport is restored after GTK lays out the rebuilt rows. If profiles are removed so the total list becomes shorter, the position is clamped to the valid range rather than showing an empty area.

The editor organizes existing settings into **General**, **Filters**, **Comparison**, and **Recovery & Safety** tabs. Each tab can scroll independently if its fields do not fit. **Cancel** and **Save** remain in a fixed footer outside the scrolling content, including on Recovery & Safety; **Restore Older…** also stays available there for existing profiles. Cancel closes without saving. You can review another tab before saving without losing edits made elsewhere.

The editor's **Left** and **Right** path fields both accept typed paths and offer **Browse…** to choose an existing local or mounted folder. Choosing a folder updates the field; it does not save the profile or clear databases until the normal Save confirmation path is used. Preserve imported settings and the existing history/path-change rules remain in effect.

## OFS profile export and import

Profiles in the header contains Export checked profiles… and Import OFS profiles… alongside the original 5.71 import. Select individual profiles or a whole group before exporting. The versioned JSON bundle preserves each selected profile's settings, including its imported flag and last-result text; no file database or log files are bundled. Export is atomic.

Import validates the complete bundle before saving anything and does not read or alter the 5.71 configuration. After confirmation, choose Skip duplicates, Rename duplicates, or Replace duplicates. Skip is the safe choice when unsure. Rename adds `(imported)` and a number when necessary. Replace overwrites matching OFS profiles only after an explicit choice; if either folder differs, its old file database is removed. These choices do not alter any unrelated profile.

## Scan

The default scan compares name, size, and last-modified time. It reads file bytes only when Binary compare is checked, and only for pairs whose size matches and whose metadata differs. While the folders are read, a window shows the profile and reading side in a heading. The current path has a stable, fixed-height, theme-aware panel with bounded middle truncation rather than wrapping that changes the dialog height. The full path remains selectable/copyable and appears in the tooltip. It also shows combined live totals for folders and files discovered, excluded by Ignore Totally, and added to the file list. It also shows elapsed time and discovered entries per second. The first completed scan stores an entry-count/duration estimate for that profile. Later repeat scans show an approximate `~` ETA: initially the previous time remaining, refined from measured pace and the fraction of previous entries discovered. Estimates can be wrong when the tree changes; paused time is excluded. Skipped or canceled scans do not replace the baseline. Those are discovery counts, not files to copy. The live preview's collapsible status panel does not lock the overview, so you can start another profile. Different profiles start immediately in parallel, each with an independent live preview. A profile already scanning shows **Scanning…** in its result column; its row button changes to **Running** and is disabled until completion, so a duplicate cannot start. Pause holds only that profile's walk. Skip Rest preserves the discovered files in a **Partial scan (review only)** comparison where the usual exclusion actions remain available. Its Start action is replaced by **Rescan**, no power actions can be chosen, and neither the UI nor CLI `--apply` can apply a partial plan. No new file history, cache manifest, or ETA estimate is saved. Cancel, or closing that preview, requests cancellation of only that profile without a partial preview; unrelated parallel scans continue. Parallel scans from one Run checked batch produce one combined summary after they finish. The bottom line of the comparison window is the plan summary: how many files and how many bytes would be copied, deleted, moved, or left to decide.

## Destination metadata cache

During live discovery, each destination side explicitly reports **cache off**, **cache reused**, an **uncached override**, or a **fresh walk**. Merely enabling cache never claims that metadata was reused; cache reuse is shown when the compatible saved snapshot is actually loaded. These states are also independent for Left and Right in Both-direction profiles.

A per-profile **Cache destination metadata (until OFS changes it)** option records a completed destination walk, not file contents, in a separate OFS `cache/` JSON manifest. Existing profiles do not enable it automatically. A later scan can reuse that metadata months later and across app restarts; there is no time-based expiry. Cached status and age are still reported, and the source is always freshly walked. While reusing a destination manifest, the scan's path panel says **Using cached destination metadata (age)**, not `.`. Use Run uncached for fresh path-by-path discovery whenever the destination may have been changed outside OFS. OFS copy/move/delete operations invalidate the cache, and the next scan rebuilds it. Changing the root or filters/masks also rejects an old manifest. A manifest is atomic and only completed scans can create it; skipped/canceled scans are not reused.

The root and filtering/mask settings must match. Bidirectional profiles keep the two possible destinations independently. A cache does not notice all external edits while it is valid. If another program or machine may have changed the destination, check the profiles and choose **Run uncached** in the header, or run `scan NAME --uncached` (`run NAME --uncached [--apply]`). That bypasses the cache for the run without disabling the saved option. This is metadata caching, not stored content hashes or automatic post-copy verification.

## File database

"Remember files and detect moves and deletions" is off until you check it. The database is SQLite at `database/<quoted name>.sqlite` under the config directory. It stores kind, symlink target, permission bits, and numeric owner/group in addition to path, size, and modification time. Existing OFS databases gain those columns in place; older entries remain regular-file records. The first run after enabling a new comparison still benefits from the normal safety undecided behavior if old metadata is not known.

The first scan with the option on records the current files and does not invent deletions. A later scan treats one missing path and one new path with the same size and time as a move, and renames on the destination when that side still has the old name. A source file that disappeared, while the other side still matches the database, becomes a delete of the other side. If the other side changed after that, or both sides changed, the row is ask. A database stored for different folders is ignored and is not overwritten. After a run, the trees are recorded again from disk.

## Comparison window

One scanned profile opens this window **as soon as scanning begins**. The result tree fills in bounded batches while discovery proceeds. Pending entries identify metadata seen on the left, right, or both, but do not make a copy/delete decision yet. **Start and completion power choices remain disabled until the complete comparison is ready.** You can use Ignore for this run or Add to exclusions during discovery; the shared rules affect future walking, rows already queued, and the resulting plan. Temporary rules do not create an incomplete destination cache or first file-history baseline; cached destination metadata is filtered for the current listing. A cancelled/incomplete result cannot be applied directly.

The scan controls share a collapsible panel above the tree. Current path occupies the left side of its information row, with discovered/filtered/added counts, elapsed time, speed, and ETA to its right. The panel collapses automatically at completion, but its final counts remain available by expanding it. Several profiles open a summary first, and each row has Preview. Completed non-copying live windows close when that combined summary appears.

Starting a comparison copy keeps the tree visible instead of opening a separate comparison-progress window. The copy controls and byte/operation totals appear in another independently collapsible panel. Completed entries are marked **Copied**, **Moved**, or **Deleted** as each operation finishes and use subdued text rather than disappearing. This display does not modify or remove remaining planned operations. Filter and folder expansion behavior stay available. Failed or canceled partial operations are not falsely marked successful, and the normal results and fresh-scan Retry Failed flow remains.

Closing a preview while it is actively scanning or copying requests Cancel and keeps the page open until that operation reaches its safe stop/completion boundary. Closing only the main overview does not cancel a scan. Per-profile application claims and cross-window completion-power guards remain active even after that overview closes.

The comparison uses two equal Left/Right header columns. The scan comparison opens maximized. Its filters can scroll independently while file counts, completion power choices, Start, and Close remain pinned below them. Reopening OFS focuses an existing main window or creates one when the overview was closed; it must not focus an empty embedded scan/copy control window.

The comparison is a folder tree. Each file row shows its size, a direction arrow, and the reason. The arrow is a small diagram: `L ──▶ R` copies onto the right, `L ◀── R` copies onto the left, `L ──✕ R` deletes on the right, `L ✕── R` deletes on the left, `L ──? R` is undecided, `L ─── R` is unchanged, and `L ··· R` is skipped. A move uses the same arrow as a copy on that side. A folder row shows the folder size beside the name and in the Size column. Its direction cell counts the arrows under it, for example `L ──▶ R  12`, and Status shows the bytes for each of those groups. The filters on the left hide rows. Start runs the whole remaining plan, including rows the filter is hiding. Right-click a file to open it, ignore it for this run, or choose **Add exclusion…**. Right-click a folder to open it, point every planned file under it, add an exclusion, set a size-review scope, or ignore it for this run. Ignore for this run is not saved. Unchanged and skipped files stay put when a folder is pointed.

Right-click also changes the plan:

- **Add exclusion…** opens an editable dialog. Choose **This profile** or **Global exclusions (all profiles)**, and **Full relative path** or **Folder or file name (any location)**. The default is the selected full relative path, relative to each profile root. Switching match types suggests that path or its name; you can edit the rule before confirming. Global additions preserve existing rules and the global Ignore Totally / Don't Copy mode. During a live scan, the new rule applies to displayed, queued, future, and finally adopted rows. Other in-flight scans retain their starting global rules and adopt it on their next scan. `*.tmp` matches a name in any folder. A path such as `cache/tmp` matches that folder and everything under it. Imported 5.71 semicolon and NBSP-separated lists are treated as separate masks. `**/.venv` matches both a root-level and a nested `.venv`; `*/cache` likewise covers a top-level or nested `cache` and everything under it. A trailing slash still means the whole folder. A lone `*` in an imported exclusion list does not hide the tree.
- The preview opens maximized. If restored to a smaller window, only filters scroll; Files shown, power options, Start, and Close stay pinned. The **Folders** toolbar holds **Expand all / Collapse all** and **Name / Size** sorting. Size sorting orders folders by aggregate bytes and files by their sizes within each parent, keeping the hierarchy. The optional **Size filter** accepts a minimum value and B/KiB/MiB/GiB/TiB units, applies to files, folders, or both, and can cover the whole preview or only a selected folder via its context menu. Folder totals follow visible descendants. These size controls are display-only: they never remove items from the plan, and Start still runs the whole plan. Individual folder collapse/expansion survives filter and exclusion refreshes. Large comparisons retain 250-row GTK batches and abandon superseded rendering batches.
- Ignore for this run, and ignore this extension for this run, drop rows without saving the profile.
- Compare files runs the compare command with the left path and the right path. Both files have to exist. The command is `meld` until you change it in Settings. `OFS_COMPARE` overrides the saved command for one launch, and the two paths are added after whatever words you set (`nvim -d` works).
- `L ──▶ R` and `L ◀── R` on a file override that row. The same two arrows on a folder point every planned file in that folder and below it. A copy or an undecided file becomes a copy. A move stays a move. A delete stays a delete, on the side the arrow points at. Leave unchanged overrides one file. Revert to scanned action puts the scan's choice back. Leave unchanged takes the row out of Start.

A saved exclusion is still there after you reopen the profile. An ignore for this run is not. Run on a row scans that profile. Run checked still scans only the checked rows. Duplicate on the overview copies the job to a new name and leaves the file database behind. Delete asks, then removes the profile and its database. The folders on disk stay.

The window opens on Affected. The other State choices are Show All, del./mov., R to L, and Unaffected. R to L means copies onto the left, moves on the left, and deletions on the left.

Existence is Show All, One Side, or Both Sides. Moved files is Show, Show Only, or Don't Show. Files to delete is Show, Show Only, or Don't Show. The groups combine.

Adjust Them is On the Left, On the Right, or Either side. It hides move rows on the other side. It does not perform the rename on the other folder. Left-to-right opens on the right, right-to-left opens on the left, and both-ways opens on Either side.

Files shown, under the filters, counts the visible rows and their sizes.

Above the list, each base folder shows Copy, Move, and Delete for that side: how many files, and their sizes. Copy on the left is files that would be copied onto the left. Those totals follow the whole remaining plan. Ignoring a row or saving an exclusion removes it from the plan and from the totals.

## Explicit copy of an entirely new folder

When you already know the matching destination folder does not exist, **Profiles → Copy new folder…** avoids a source/destination comparison walk. Check exactly one enabled one-way profile, then choose a subfolder under its source side. The same action is available by right-clicking a folder in a complete comparison. A skipped review-only comparison hides/rejects this action; use its exclusions and Rescan controls first. It is an independent copy-only command, not an application of a normal scanned plan.

Confirm the exact source and destination shown. OFS rechecks that the destination is absent, streams the source tree in chunks through the existing per-file atomic copier, and installs a temporary sibling with Linux `renameat2` using `RENAME_NOREPLACE`. Another program creating the destination during the copy therefore keeps its data. No overwriting or deletion is part of this action. Existing global/profile/session masks, include/size/age rules, disabled status, and symlink/ownership options still apply. Root-level and nested `*/cache` exclusions prevent that tree from being copied. Root selection, relative `..` escapes, and Both-direction mode are refused. A top-level preserved link must use a normal comparison.

Pause and Cancel operate between chunks. Empty folders are copied and directory timestamps are captured after their contents. Because no comparison is performed, the overall progress bar pulses with an unknown total instead of inventing a percentage; current-file bytes, copied files/bytes, errors, elapsed time, and speed are still updated. Failure/cancel cleans up the temporary folder and any still-empty newly created parents; no final folder is installed. Results, history/cache invalidation, and a log are written afterward. The file-history option may independently refresh the current trees after the transfer, just as after other runs. **Retry Failed…** performs the normal fresh scan instead of replaying the old folder action or overwriting the now-existing destination.

## Safety confirmation

Start opens Safety Confirmations Required when the plan still deletes at least one file. Nothing is copied or deleted until you choose.

The text names the profile and, for each side that would lose files, the folder and `N of M (percent)`. `M` is every file in the comparison list, including unchanged files. The first 200 paths are listed. A folder is listed when the deletions on that side are at least half of the files in that folder.

- Confirm Deletions runs the plan, including deletes.
- Continue Without Deletions runs the copies and the moves and leaves the planned deletes in place.
- Do Not Continue changes nothing. Closing the window does the same.

If the window is still open after 120 seconds, the run continues without deletions. Enter is that same choice.

The profile editor has three additional opt-in safeguards. Delete limit blocks Confirm Deletions when either side's planned deletions exceed the specified percentage of the complete remaining comparison; zero disables the limit. Block deletion of every file in a folder blocks confirmation when all scanned files on that side of any folder would be deleted. Ignore Totally files are invisible and do not count toward that folder. Never delete files blocks every file-delete action; ordinary empty-folder cleanup after moves remains possible. These are also Multi Edit fields.

Blocked plans may still Continue Without Deletions, or the user can change the profile safeguards. Confirmation is disabled; the timeout cannot turn a blocked plan into a deletion run. The apply engine independently enforces these limits even outside the confirmation window. A direct apply without a complete listing is refused when a percentage or folder limit needs one. `run --apply` refuses a protected plan before any copies, moves, deletes, or logging. Existing/imported profiles retain their original safeguards by default.

When the plan deletes nothing, Start goes straight to progress. The comparison list is the confirmation for those copies and moves.

A row marked ask is skipped and reported as left undecided. `run --apply` refuses the whole run while any ask remains, and it writes no log in that case.

## Progress

Copying runs off the UI thread and stays serial. The progress window shows the current relative path, operation count, processed/planned copy bytes, copied/deleted/moved/error counts, elapsed time, active-run speed, ETA, an overall byte-weighted bar, and a current-file bar. Move/delete-only plans use operation count for the overall bar.

Pause and Resume work between copy chunks, including inside a large file. Cancel can stop an in-progress copy. Each file is written to a unique temporary sibling and atomically replaces the destination only when complete, with metadata preserved. With Older enabled, the old destination is archived after the new copy succeeds. Cancellation removes the incomplete temporary file and leaves the prior destination intact. Closing the progress window is Cancel, and it stays until the run has stopped.

Settings has a shared copy speed limit in MiB/s with **Unlimited**, **1**, **10**, **100 MiB/s**, and **Custom** choices; zero is unlimited. It applies to GUI runs and `run --apply`. These are mebibytes per second, not network megabits. Progress counters use fixed-width monospaced fields so changing values and Paused do not move neighboring labels.

The preview's **After completed copy** selector has **Do nothing** (default each run), **Sleep**, **Hibernate**, and **Shut down**. A selected power action runs through Linux `systemctl` only after that copy completes without errors or cancellation and no other copy is still active. Refused/system command failures are explained. It is an explicit per-run action, not scheduled or unattended synchronization.

## Results and logs

Copying Results shows whether the run finished, finished with errors, or was stopped. Failed runs offer Retry Failed with confirmation; OFS then rescans the current folders and builds a fresh preview instead of replaying stale operations. Retry follows the normal deletion safety checks. Where operation errors retain a trusted relative path, **Exclude failing path(s)…** saves literal path rules after confirmation, while **Exclude common folder…** uses the shared relative parent, for example `project/service/volumes`. These change only the profile exclusions, not folders or files, and absolute paths in OS error details are not used. There is no common-folder action when the failures share no subfolder below the profile root. Left and Right columns show files copied to that side, files moved on that side, and files deleted on that side, each as a count and a size. Folders created and folders removed are single totals. New parent folders for a copy, a move, or an `Older` archive count as created. Empty folders left behind by a delete or a move are removed. The profile folder itself stays.

View Log opens the text file for that run. Each run writes one file in `logs/` under the config directory:

`<profile> - YYYY-MM-DD HH.MM.SS.log`

`/`, `\`, and `:` in the profile name are replaced. The text has the profile name, both paths, the safety choice, one line per planned change, and the same totals. `run --apply` prints the totals and the log path.

The overview row stores a short last result: how many files were copied, deleted, and moved.

## Not in this version

Scheduler, unattended runs, partial files, ZIP, internet protocols, and mail. Versioning on or off is not stored as a per-profile flag in this `.cfg`, so import leaves `Older` off. The deletion timeout and the half-folder callout are fixed, not profile settings.
